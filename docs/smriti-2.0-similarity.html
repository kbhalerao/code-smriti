Fingerprints Over Vectors

2026-08-18design note 01internal

Findings

  • Similarity search works on existing infrastructure. Ranking below the top three is noise.
  • The embedding cannot separate a renamed structural clone from unrelated code. Its signal for code is identifier strings.
  • AST k-gram fingerprints separate the classes completely. No threshold to tune, no LLM.

Model

A fingerprint is a set of hashes, not a vector; it is compared by set overlap, not cosine. Three signals and a partition.

signalquestionrole
Fingerprint overlapIs this the same code? Primary. Jaccard over k-gram hashes. A 20% edit retains ~65% of k-grams against a 0.14 random ceiling.
Embedding cosineIs this about the same thing? Demoted. Only for token-disjoint reimplementations.
AST shape metricsLoop depth, branches, arity, fan-out Pre-filter and rerank feature. Random pairs average 0.85.
Tree positionWhich repo, module, file Not a distance. Converts a score into a verdict: refactor within a repo, port across two, boilerplate across forty.

Records and queries

fingerprint_unit          // one per outermost function/class, first-party only
  unit_id = hash(repo_id, file_path, symbol_name)   // stable across commits
  repo_id, file_path, symbol_name, lang, start_line, end_line
  content_hash            // a field, never part of the key
  fp[]                    // k-gram hashes, identifiers -> ID, literals -> LIT
  shape{}                 // loop_depth, branches, params, calls, nesting
  is_vendored

fingerprint_df            // corpus-frequency table
  fp_hash -> n_repos, n_families

Query A - intra-repo duplication
  seed rare fp (df <= 3) -> candidates in same repo -> Jaccard >= 0.7 -> union-find
  rank by (copies - 1) x median_lines x corpus_rarity

Query B - port a fix
  commit hunks -> path join into sibling repos -> match hunk pre-image
  classify: already-fixed | applies-clean | drifted | absent

Build options

optionbuyscosts
A Query-time, no index Answers in days. No schema change, no migration, no storage. No frequency table, no incremental updates, nothing queryable by RAG or KPI.
B Sibling structural store Both queries at speed, incrementally maintained, frequency table present. No risk to existing search. Two stores to keep coherent. Needs the vendored classifier first.
C Unified symbol spine One record, one truth. Identity rot fixed at the root. Full re-ingest of 94K symbols and an FTS schema change, search degraded while it lands.

Recommendation: B. The corpus-frequency table separates a refactoring target from boilerplate and needs to be persistent. C is the end state, reachable from B incrementally; the identity work is the same either way.

Sequence

  1. Vendored-code classifier. Path heuristics, minification detection, known-library fingerprints.
  2. Collapse mirror repos at Jaccard 1.00.
  3. Fingerprint pass and frequency table. The prototype exists; it needs productionising.
  4. Intra-repo duplication. Self-contained; 887 clusters waiting.
  5. Porting. Adds a path map and the four-state classifier on the same store.

Method

  • Measured 2026-08-18 against 296 clones in $REPOS_PATH and the live code_kosha bucket.
  • Embedding figures use nomic-embed-text-v1.5 with the search_document: prefix, matching the ingestion path.
  • Fingerprints are 5-grams (Python benchmark) and 6-grams (corpus prototype) over a token stream with identifiers and literals collapsed to placeholders.
  • The near-clone bucket used difflib.quick_ratio, an upper bound; treat 20% as optimistic. The 67.6% byte-identical figure is exact.
  • Prototype sources: dedup.py, cluster.py, port.py, discrim.py, realcorpus.py.
