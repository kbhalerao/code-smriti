The Judgment Layer

2026-08-19design note 02internal

Purpose

  • Three-pane browser over the smriti corpus: document hierarchy, source, metadata.
  • Records whether a generated summary is any good. Presence is measured across the corpus; quality has never been measured.
  • Not a defect-discovery tool. Every defect found to date came from aggregate measurement; per-file counts looked correct throughout.

Preconditions

  • Annotations anchor to document_id. Under commit-keyed identity every re-ingest orphaned every annotation, so this was not buildable before v2.
  • Documents are now upserted in place, so the judged text is mutable. Annotations must snapshot what they judged.

Deployment

  • Page lives in Chief of Staff. Shared JWT secret and user table; no separate credential.
  • smriti exposes /api/inspect/*; the page is a presentation-only client.
  • Schema knowledge stays on the smriti side. A page reading code_kosha directly would have kept reading symbol_name after the semantic_unit split.
  • api-server already mounts the repository clones at /repos; CoS needs no mount.

Interface

Left — document tree

  • smriti's hierarchy, not the filesystem: repo_summary → module_summary → file_index → symbol_index / semantic_unit.
  • Filesystem overlaid so a file present on disk with no file_index is visible. Neither tree shows that alone.
  • Files whose directory has no module_summary are marked.

Centre — source

  • Read from disk. smriti stores no file content.
  • Each symbol's start_line/end_line tinted over current disk content.
  • content_hash compared against a live hash of the span. Documents predating the field report unknown, not stale.
  • Gutter rail: one column per nesting depth, coloured by verdict.

Right — ancestry

  • Symbol, file, module and repository summaries shown together.
  • Outstanding defects are rollup defects; ~472 file→module links dangle.

Neighbours

  • Top-k by the document's own stored vector. No model in the frontend.

Verdicts

  • A verdict axis, not a taxonomy. Failure modes go in the note field.
  • generic is schema-valid, non-empty and correctly attributed, so no automated check detects it.
  • misattributed observed: listings/tests/test_realistack_helper.py indexed under RealstackAPI.get_users and get_cities, neither defined in that file.

Annotation document

field groupcontents
targettarget_id, target_type
judgmentverdict, note, author, created_at
anchorrepo_id, file_path, symbol_name, start_line, end_line, content_hash
snapshotcontent, summary_source, enrichment_level, pipeline_version, schema_version
  • Append-only. Current verdict is newest per (target_id, author).
  • Client sends target and judgment only. Snapshot is read server-side; a client-supplied snapshot allows a stale tab to judge replaced text.
  • Provenance is snapshotted because a summary judged under one model is not evidence about another.
  • No embedding; not indexed in code_vector_index.

Anchor stability

casebehaviour
Named symbol, re-ingestedId unchanged.
Named symbol, movedId unchanged.
Symbol renamedNew id; annotation dangles.
Unnamed or colliding symbol, movedSpan-keyed; new id; annotation dangles.
  • Dangling annotations are re-attachable by content_hash, or shown as stale. Never silently dropped.

Sampling

  • /sample returns documents with no judgment, ordered by document_id — a hash of location, so ordering is arbitrary with respect to content and reproducible.
  • Judging only what is browsed biases the set toward what was browsed.
  • Scoped to one repository; corpus-wide ordered scans have no index.

Open decisions

  • Indexes. Children of a file, children of a module, and annotations by target had no index. Resolved by per-repo fetch and six added indexes.
  • Highlighting. Span tint is free. Syntax colouring costs a dependency (shiki).
  • Authorship. Single-author. The (target, author) key admits a second.

Out of scope

  • Findings queue. The same cohorts are already reachable by ad-hoc N1QL.
  • Summary editing. A human-written override must survive re-ingestion, which is a different object.
